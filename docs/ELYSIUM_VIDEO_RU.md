# Gemini Video через Elysium — KadroGen 2.0.3

Схема: FastGen создаёт изображения, Gemini Omni Flash 1.2 через Elysium оживляет
их, ElevenLabs озвучивает сценарий. Текстовая модель Elysium настраивается отдельно.

## Настройка

1. На экране выбора сервисов оставьте FastGen для картинок.
2. На экране «Доступ» в строке «Оживление картинок» выберите
   «Gemini Omni 1.2 · Elysium».
3. Введите свой ключ Elysium. Если он уже введён для GPT, используется тот же ключ.
4. Адрес API: `https://elysiumai.garden/v1`. В строке Elysium можно задать свой адрес.
5. Начните с разрешения 720p. Модель: `google/gemini-omni-flash-1.2`.
6. «Проверить без генерации» проверяет авторизацию и наличие модели в медиакаталоге.
   Эта кнопка не создаёт клип и не доказывает доступность платного запуска.
7. В озвучке выберите «ElevenLabs напрямую», свой ключ и голос.
8. Для оживления используйте «Только видео», «50 на 50» либо «Оживить первые».
   Режим «Только картинки» без оживления не обращается к видео API.
9. Первым запустите предпросмотр 30 секунд. Генерации оплачиваются по тарифу Elysium.

## Картинки и ссылки

Elysium принимает первый кадр по доступной HTTPS-ссылке. Новые картинки FastGen
сохраняют ссылку результата в файле `.source.json` рядом с PNG и проверяют её
соответствие содержимому картинки. Ссылка также переносится через кэш раскадровки.
Старые локальные картинки без ссылки, картинки из других сервисов без сохранённой
ссылки и устаревшие ссылки нельзя автоматически отправить этим путём. Для такого
плана создайте новый вариант картинки через FastGen. Программа не пересоздаёт
платные изображения самостоятельно ради получения ссылки.

## Задания и восстановление

Используется `/v1/videos`, операция `generate`, первый кадр `input.first_frame_url`.
Длительность округляется вверх до целого числа секунд и ограничена 3–15 секундами.
ID задания сохраняется в `projects.sqlite`. При остановке, сбое опроса или скачивания
повторный запуск с теми же картинкой, движением и настройками продолжает проверять
то же задание. Завершённый файл проверяется FFprobe и публикуется атомарно.

Если отправка оборвалась до получения ID, её результат неизвестен. Автоматический
повтор запрещён: проверьте историю Elysium. Отклонённые завершённые задания также
не пересоздаются автоматически; исправьте план или создайте новый вариант.

Видео этого провайдера и разрешения имеют отдельный кэш. FastGen не используется
как запасной видеопровайдер и его `video.generate=false` не блокирует Elysium.
При сборке применяется выбранная озвучка ElevenLabs, а не речь из видеоклипа.

## Проверка реализации

Проверены протокол на подставных ответах, защита от повторной платной отправки,
восстановление ID, раздельный выбор провайдеров, загрузка настоящего тестового MP4,
FFprobe и элементы интерфейса в браузере. Живая платная генерация не выполнялась:
пользовательский ключ в среду не передавался. Качество и реальный доступ модели
проверяются первым коротким запуском в программе.

Официальные источники:
- https://elysiumai.garden/docs/api/video
- https://elysiumai.garden/docs/models/gemini-omni-flash-1-2
- https://elysiumai.garden/v1/media/models

## Диагностика статуса (2.0.5)

HTTP-ошибки показывают этап, маршрут, код и сообщение Elysium без ключей и приватных ссылок. При отказе GET /videos/{id} ID остаётся сохранённым и отображается в ошибке. Это отказ получения статуса уже принятого задания; он не доказывает отказ генерации или нехватку баланса. Не создавайте новое платное задание автоматически. Для установления причины сравните ID с задачей в кабинете Elysium. Обновление улучшает диагностику, но не отменяет серверный запрет доступа.

## Ошибка создания клипа (2.0.6)

При HTTP 200 и status=failed показываются причина из error/metadata.error/failure_reason и ID задания. Причина сохраняется в projects.sqlite; повторный запуск с теми же данными читает статус старого задания, включая старые отказы из предыдущих версий, без нового платного POST. Если сервер не сообщает причину, приложение указывает это явно. Исправлен сброс счётчика готовых клипов при опросе следующего задания. Сама причина отказа сервиса не исправляется этим диагностическим обновлением.


## Kling 3.0 (2.0.7)

«Доступ» → «Оживление картинок» → «Gemini / Kling · Elysium». В строке
«Video · Elysium» выберите `Kling 3.0 · kling-3.0/video`. Ключ и адрес Elysium
общие с Gemini и текстовыми моделями. В правах ключа должен быть разрешён Kling.
FastGen продолжает рисовать кадры, ElevenLabs — озвучивать. Проверка без генерации
проверяет выбранную видеомодель; не создаёт платный клип.

Standard (`std`) выбран по умолчанию; Pro (`pro`) доступен отдельно. Разрешения
720p/1080p относятся к Gemini, Kling получает свой параметр mode. 4K не включён.
Kling отправляется через POST /videos, operation=generate, input.image_urls=[URL],
строковая duration от 3 до 15, sound=false, multi_shots=false, multi_prompt=[].
Схема сверена с https://elysiumai.garden/v1/media/models.

По каталогу на момент проверки Standard без звука стоит $0.105/с, Pro — $0.135/с
(USD, не внутренние $API). Минимальный клип 3с — $0.315/$0.405. Фактическое списание
и доступ определяет Elysium. Смена Gemini на Kling создаёт новые платные клипы
для выбранных к оживлению планов. Неудачные задания Gemini не отправляются в Kling
автоматически. Старые клипы Gemini сохраняются в своём кэше; для продолжения
ожидания Gemini верните его модель и прежние настройки. Картинки и озвучка
переиспользуются при запуске того же проекта с теми же исходными параметрами.

Задания Kling Standard/Pro раздельны; восстановление ID, остановка при неизвестном
результате POST, диагностика ошибок и проверка MP4 такие же, как у Gemini.
Включено и в 30-секундный предпросмотр. Живую платную генерацию Kling при разработке
не выполняли; протокол, восстановление и интерфейс проверяются на тестовых ответах.


## Восстановление ссылок (2.0.8)

Исправлено восстановление `.source.json` для уже существующего PNG и публикация
ссылки в уже существующий кэш. Перед новой отправкой видео приложение ищет
сохранённые ссылки в `jobs`, включая `storyboard-assets` и предыдущие сборки.
Ссылка применяется только при точном совпадении SHA-256 изображения. Картинки
не изменяются, изображения и озвучка заново не генерируются ради поиска.
Невалидные данные и ссылки от другой картинки игнорируются.

Если ссылка ни разу не сохранялась либо все её копии удалены, восстановить
публичный адрес из одного PNG нельзя. Для этого случая ошибка теперь показывает
номер плана и отсутствие отправки в Elysium. Не нужно удалять весь проект или
все заготовки. Документированного отдельного upload API для видео не найдено;
эта версия не добавляет неподтверждённый маршрут или сторонний хостинг файлов.
При уже сохранённом ID задания ссылка на картинку повторно не требуется: опрос
и скачивание продолжаются без восстановления и без нового POST.


## Hailuo 2.3 Standard через Elysium (2.0.9, прежний способ передачи)

**Обновление: data URI отклонён Elysium. Используйте HTTPS-загрузку из 2.0.10 ниже.**

«Доступ» → «Оживление картинок» → «Hailuo / Gemini / Kling · Elysium» →
«Hailuo 2.3 Standard · 768p · 6 s». Ключ и адрес Elysium те же. Ключ fal не нужен.
FastGen создаёт картинки, выбранная озвучка (например ElevenLabs) сохраняется.
Это Hailuo Standard из каталога Elysium, не endpoint Hailuo Fast на fal.

Проверенная схема живого каталога: model=
`hailuo/2-3-image-to-video-standard-provider-4`, operation=generate,
input: prompt, image (URI), duration=6 (целое), resolution=768p, aspect_ratio=16:9,
generate_audio=false. По каталогу $0.15 USD за клип до скидок аккаунта, не $API.

Приложение кодирует настоящий локальный PNG/JPEG/WebP в data URI в input.image.
Сохранённый download_url, старые .source.json и перерисовка ради ссылки не нужны.
Файл проверяется Pillow, локальный лимит 20 МБ. URI допускает data URI по синтаксису
схемы; фактический приём такого ввода конкретным маршрутом Elysium ещё требуется
подтвердить первым запуском на пользовательском ключе. Это не проверка живой
платной генерации: при разработке ключ не передавался. Если сервер отклоняет
inline-ввод, приложение показывает реальную ошибку; не отправляет другие форматы
или модели автоматически. Неизвестный результат POST блокирует повторную отправку.

ID сохраняется до опроса, остановки и скачивания. При перезапуске используется
тот же ID; законченные клипы и остальные медиа переиспользуются. У Hailuo отдельный
кэш, не затрагивающий Gemini/Kling. Смена модели создаёт новые оплачиваемые клипы
для выбранных к оживлению планов. Предпросмотр 30с поддерживается. Сам клип 6с,
при монтаже обрезается или удерживает последний кадр по длительности плана;
при привязке к речи применяется существующий механизм подгонки скорости.

Данные изображений, секреты и приватные ссылки в ошибках скрываются. HTTP422
показывает detail сервера, чтобы отказ формата не выдавался за проблему ключа.

## Публичные ссылки для Hailuo (2.0.10)

Живой ответ Elysium подтвердил: data URI для видеореференса не принимается
(HTTP 400, video reference must be a public HTTPS image URL). Способ из 2.0.9
заменён загрузкой готового PNG/JPEG/WebP в https://uguu.se/.

Пользователь разрешил отдельное хранилище. Uguu работает без ключа и хранит
файлы 3 часа; ссылка публичная, доступна каждому, у кого она есть. В запрос
хранилищу передаётся только картинка под общим именем frame.png, без ключа
Elysium, текста сценария и имени проекта. Локальный кадр не меняется.

Перед отправкой Hailuo приложение скачивает публичный файл отдельным запросом
без авторизации и сверяет SHA-256 с исходником. Только после совпадения
отправляется POST /videos с input.image=https://… . Ошибка загрузки/проверки
останавливает работу до платного видеозадания. Битые и слишком большие (>20 МБ)
картинки останавливаются до загрузки. Ключа хранилища и ручного получения ссылок
не требуется.

Проверенные ссылки кэшируются по SHA-256 в projects.sqlite с датой истечения.
При повторном использовании ссылка проверяется публичным GET; устаревшие ссылки
перезагружаются. Картинки, озвучка и готовые клипы не пересоздаются ради URL.
Уже принятые видеозадания продолжаются по ID без загрузки исходной картинки.
Идентичность операций 2.0.9 сохранена: известные/неопределённые задания не будут
отправлены повторно. HTTP400 rejected из 2.0.9 допускает новую HTTPS-отправку;
неопределённые POST после 502 остаются заблокированными, включая старый Kling.

На тестовом PNG проверена настоящая загрузка в Uguu и публичное скачивание:
HTTP200, image/png, точное побайтовое совпадение. Платная генерация Hailuo через
пользовательский ключ не выполнялась; доступ Elysium к ссылке и качество
проверяются первым клипом на ключе пользователя.

Документация хранилища: https://uguu.se/api и https://uguu.se/faq .


Актуальные модели Kling, Gemini и Grok, общий HTTPS-загрузчик и режим единых локаций описаны в [VIDEO_MODELS_RU.md](VIDEO_MODELS_RU.md) (2.0.11).
