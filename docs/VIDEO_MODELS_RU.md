# Видео и единые локации — 2.0.11

## Видеомодели Elysium

«Доступ» → «Оживление картинок» → «Kling / Gemini / Grok · Elysium».
Ключ и адрес Elysium прежние. FastGen рисует, выбранная озвучка (ElevenLabs)
используется в сборке. Hailuo не является основным вариантом; прежняя настройка
видна только если сохранена в старом конфиге. Для перехода явно выберите новую модель.

- Kling 3.0: `kling-3.0/video`, `generate`, `image_urls=[HTTPS]`, duration строка
  от 3 до 15, mode std/pro, sound=false, multi_shots=false, multi_prompt=[].
- Gemini Omni: `google/gemini-omni-flash-1.2`, `generate`, first_frame_url=HTTPS,
  duration целое от 3 до 15, resolution720p/1080p.
- Grok: `x-ai/grok-imagine-video`, `image-to-video`, image_urls=[HTTPS], index=0,
  duration="6", aspect_ratio16:9, mode=normal, resolution480p/720p/1080p.
  Используется стандартная длительность 6с из схемы. По каталогу до скидок:
  480p $0.108, 720p $0.2025, 1080p $0.36 USD за клип. Это не внутренние $API.

Для всех моделей готовые картинки загружаются в Uguu без ключа хранилища, с
публичным доступом по ссылке до 3 часов. Программа скачивает и сверяет SHA-256
до платного видеозадания. Ключ Elysium, имя проекта и текст сценария не уходят
в хранилище. Старый download_url FastGen и data URI не требуются. Сбой хранилища
останавливает работу до POST /videos. Уже сохранённый ID опрашивается без загрузки
исходника. Неопределённые отправки после 502 остаются заблокированными; это обновление
не сбрасывает их и не доказывает отсутствие задания/списания. GET-опрос и скачивание
завершённых заданий сохраняются. Для диагностики неизвестной отправки нужен ответ
Elysium; приложение не угадывает её результат и не делает платный повтор.

Для первой пробы Grok: 480p, «Только картинки» + «Оживить первые: 1», тот же
предпросмотр из сохранённой раскадровки. Новая модель создаёт новые платные клипы.
Формат Grok сверен с живым /v1/media/models. Платные запуски на пользовательском
ключе при разработке не выполнялись; доступ и результат проверяются первым клипом.

## Единые локации

«Доступ» → «Единые локации» → «Общий интерьер для одной комнаты».
Режим включается отдельно, по умолчанию выключен для сохранения старых проектов.

Текстовая модель группирует планы одной физической комнаты, в том числе возвращения
в неё позже. Отдельные квартиры/комнаты и лестничная клетка не должны объединяться
по одному слову «коридор». Непонятные/абстрактные планы получают пустую привязку.
Анализ идёт пачками до 16 планов и сохраняется; это дополнительные текстовые запросы
по тарифу выбранного сервиса. В предпросмотре анализируются только выбранные планы.

Первый план комнаты становится опорным после завершения автоотбора. Отдельная
генерация эталонного изображения не требуется. Следующие планы получают готовый
опорный кадр первым референсом и инструкцию сохранять архитектуру, двери/окна,
материалы, мебель и цвета. Ракурс, персонажи и действие могут меняться. Другие
комнаты создаются параллельно; кадры одной комнаты — последовательно. Если опорный
кадр не получен, зависимые кадры не отправляются вслепую.

С включённым автоотбором модель сравнивает два изображения: слева эталон, справа
новый кадр; проверяется только правый кадр. При отказе используется существующий
цикл до двух перерисовок. Если все варианты с замечаниями, существующий механизм
сохраняет лучший и показывает число проблемных кадров. Режим повышает связность,
но не гарантирует идеальную одинаковость генераций: просмотрите результат перед
оживлением. Исправлена ошибка, когда одобренный новый вариант мог заменяться старым
забракованным вариантом с более высоким баллом.

Включение имеет отдельный визуальный кэш и создаёт новые кадры выбранного отрезка;
старые картинки, озвучка и сборки не удаляются. Изменение опорного плана обновляет
зависимые планы этой комнаты, не других локаций. Перерисовки оплачиваются сервисами.
Для проверки интерьеров сначала используйте 30-секундный предпросмотр, «Только
картинки» и «Оживить первые: нет». После проверки можно включить выбранную видеомодель.


## Восстановление текстов сцен в 2.0.12

«Тексты сцен» — отдельная настройка от модели оживления. Если FastGen исчерпал часовой лимит текстов и в настройках сохранён ключ Elysium, программа использует выбранную текстовую модель Elysium. Эти запросы оплачиваются по тарифу Elysium. Чтобы сразу работать через него, выберите Elysium в строке «Тексты сцен». Не выбирайте видеомодель в качестве текстовой.

Готовые промпты сохраняются после каждой пачки. Неполный ответ больше не удаляет удачные сцены: следующий запуск дописывает недостающие. Ошибки доступа 401/403 останавливают новые запросы текущего этапа; журнал показывает причину и реальное количество готовых промптов. Генерация картинок не запускается по временным заглушкам. Озвучку, транскрипцию, готовые кадры и базу заданий удалять не нужно.


## 2.0.13: недостающие сцены и подача исходника

Если в 2.0.12 готовы 125 или 150 из 151 промпта, сохранённые результаты остаются пригодны. В 2.0.13 сцены получают устойчивые ID. Полный ответ с нумерацией внутри пачки сопоставляется с этой пачкой, неполный неоднозначный ответ запрашивается меньшими группами, вплоть до одной сцены. Уже принятые промпты не переспрашиваются. Для продолжения старого задания сохраните его настройки и перенесите config.json, jobs и projects.sqlite.

При новой подготовке исходного видео программа отдельно анализирует его звук, чтобы взять темп, паузы, относительный диапазон интонаций и манеру диктора. Пресеты выбирать не нужно. Для короткого исходника анализируется не больше его длительности; для длинного — до 60 секунд звука из трёх мест. В пробном режиме используются только звуковые фрагменты выбранных 30 секунд.

Анализ выполняется Gemini через существующий ключ Elysium (нативный маршрут Gemini, google/gemini-3.6-flash) либо через прямой ключ Gemini, если ключа Elysium нет. Это отдельный оплачиваемый запрос анализа звука. Фрагменты передаются в самом запросе, без публичного хостинга. Успешный разбор кэшируется. Если у модели нет доступа к аудио или ответ непригоден, программа показывает ошибку и не выдаёт разбор текста за прослушивание. Без ключей Elysium/Gemini выводится сообщение, что анализ подачи не выполнен.

FastGen/Gemini TTS получает инструкции на основе услышанной подачи, сохраняя выбранный голос и слова нового сценария. ElevenLabs Multilingual v2 получает приближённые настройки темпа и выразительности, а также текст соседних частей для более ровных стыков. Этот движок не умеет точно повторять произвольный интонационный рисунок по текстовой инструкции. Ни один из этих путей не обещает полного совпадения исполнения.

Старые озвучки автоматически не заменяются. Чтобы услышать подачу по источнику, заново подготовьте короткую пробу по YouTube-ссылке. Она создаёт отдельную версию с новыми таймингами. Сначала оцените её, затем запускайте длинный ролик. Голос остаётся выбранным в настройках; клонирование личности диктора не добавляется.

Документация протокола: https://elysiumai.garden/docs/api/gemini-compatible ; https://ai.google.dev/gemini-api/docs/audio ; https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices .


## 2.0.14: звук исходника и проверки сервисов

Для анализа картинок YouTube может отдать видеоряд без аудио. Теперь перед разбором подачи проверяется аудиодорожка; если её нет, программа отдельно получает исходный звук и кэширует его. Скачанный видеоряд, картинки, озвучка и готовые промпты не удаляются. В 30-секундной пробе уже есть звук выбранного отрезка; весь исходник для неё не скачивается.

Проверка Elysium теперь бесплатная: проверяет авторизацию и наличие выбранной модели в каталоге /models. Она не обещает успешную генерацию и не расходует токены на тест с лимитом 200. Чат и автоотбор изображений распознают обычный JSON и SSE, включая поток, ошибочно помеченный сервером как JSON. Для OpenAI-моделей с полным ID вроде openai/gpt-5.4 используется режим JSON; нативные параметры reasoning-моделей правильно распознаются и с префиксом провайдера. Непригодные HTTP-ответы не передаются модели для ремонта JSON.

ElevenLabs проверяет структуру списка голосов, различает пустой ответ, HTML/перенаправление и неправильный JSON. Ключ не объявляется неверным только из-за ошибки разбора. Секреты и содержимое серверной HTML-страницы не выводятся; показаны HTTP-статус, маршрут и тип ответа. Запросы с ключом не следуют произвольным перенаправлениям. Доступ сервиса из пользовательской сети нельзя подтвердить локальными тестами: проверка выполняется в самой программе.


## 2.0.15: восстановление анализа озвучки

Анализ исходного звука теперь запрашивается с явной схемой полей Gemini responseSchema и лимитом 6000 выходных токенов вместо 1600. Полученный текст разбора сохраняется до проверки JSON. Для законченного ответа с нарушенным форматом допускается одно текстовое исправление, без повторной отправки аудиофрагментов и без придумывания отсутствующих наблюдений. Если в исходном ответе явно названы числовые измерения, исправление не может их менять.

Успешные старые разборы продолжают использоваться. После сбоя при исправлении формата повторный запуск использует уже полученный текст. Пустые, обрезанные и содержащие только размышления ответы не считаются результатом; автоматический повтор аудиозапроса в том же запуске отсутствует. Если сам разбор непригоден, новый ручной запуск может получить его заново.

Кнопка «Отчёт» доступна и на экране проверки сценария. Полный стек ошибки сохраняется в videogen.log с удалением известных ключей. Этапы разбора озвучки также попадают в журнал.


## 2.0.16: продолжение картинок с едиными локациями

Временный отказ по опорному кадру больше не прерывает всю обработку до второго прохода. После остальных групп повторяются только недостающие картинки: сначала опорный кадр комнаты, затем зависимые планы. Если сбой произошёл в обычном плане, остальные планы той же комнаты продолжают создаваться с уже готовым опорным кадром.

При повторном запуске готовые файлы сохраняются. Отказ фильтра содержимого не отправляется повторно; причина выводится для конкретного плана. Если опорный кадр не получен и после второго прохода, его зависимые планы ожидают его и не оплачиваются как независимые генерации. Ручная перерисовка опорного кадра также выполняется перед зависимыми. Счётчик показывает количество готовых изображений, а не число обработанных ошибок.

Для версии 2.0.15 предусмотрен отдельный архив с новым KadroGen.exe. Закройте программу и замените только этот файл в существующей папке. Совместимость остальных файлов проверяется сравнением собранных пакетов; config.json, jobs и projects.sqlite не входят в обновление. Полный архив остаётся доступен для чистой установки.
